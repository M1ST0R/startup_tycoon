# Startup Tycoon — объединённая версия

Готовый проект находится в `C:\Users\admin\sturtup_tycoon`. Объединены `startup_tycoon-gh_1` и `startup_tycoon`; исходные папки сохранены без изменений.

## Возможности

- Графический офис, 20 спрайтов, портреты, анимация работы, энергия выбранного сотрудника и комнаты по четыре места с расширением до десяти сотрудников.
- 82 имени: 35 мужских и 47 женских, по 60 уникальных фамилий каждого пола и 16 прозвищ. Пол определяет имя и спрайт; формулировки журнала и реплик сохранены.
- Реплики сотрудников с очередью, приоритетами и защитой от повторов. Облачка показываются в текущей комнате.
- Шесть форс-мажоров из `gh_1`: предложения инвестора, события команды и офиса. Решение влияет на деньги, репутацию, продукт, настроение или энергию.
- Сохранён ранее согласованный выбор сложности: лёгкий, средний и хардкор. Источник восстановления сложности — локальный коммит `76a54ae`.
- Регистрация, вход, автосохранение и защита от конфликтующих сохранений.

## Запуск

Проверено на Node.js 24.20.0. Зависимости уже установлены; при необходимости их можно восстановить командой `npm ci`.

```powershell
cd C:\Users\admin\sturtup_tycoon
npm start
```

Открыть <http://127.0.0.1:3000>, зарегистрировать аккаунт и выбрать сложность. Для разработки доступен `npm run dev`.

`.env` создан из `.env.example`: сервер слушает `127.0.0.1:3000`, отдельная база создаётся при первом запуске в `data/game.db`. Аккаунты, прогресс, `.env` и Git-метаданные исходных проектов не перенесены. Итоговая игра начинает работу с чистой базой.

## Сложность и события

| Режим | Скорость работы | Трудоёмкость проектов | Частота форс-мажоров | Цель: клиенты / репутация |
| --- | --- | --- | --- | --- |
| Лёгкий | ×1,20 | ×0,80 | ×0,5 | 80 / 30 |
| Средний | ×1,00 | ×1,00 | ×1 | 100 / 40 |
| Хардкор | ×0,75 | ×1,50 | ×2 | 180 / 60 |

Форс-мажоры не появляются без сотрудников. При первом найме проводится отдельная попытка события; последующие наймы её не повторяют. Обычные проверки сохраняют интервал минимум в восемь игровых тиков. Пока открыто событие с паузой, игровой таймер остановлен. Решение, игнорирование и отсрочка восстанавливают прежнюю паузу игрока.

«Отложить» возвращает событие через 30 секунд. Выход, новая кампания, импорт и загрузка очищают старые окна, очередь и отложенные таймеры. Старые кнопки и callbacks не могут изменить другую игру. Данные событий хранятся в `force-majeure.json`; примеры добавления — в `FORCE-MAJEURE-README.md`.

## Совместимость

HTTP API и формат сохранения `v: 1` сохранены. Клиент и сервер одновременно сохраняют `gender`, `appearance`, `difficulty` и `flavor`, включая историю реплик.

Старые сохранения обеих версий читаются с сохранением прогресса, имён и подходящих спрайтов. Недостающий пол определяется по имени, затем по сохранённому спрайту, затем стабильно по ID. Пустые имена получают уникальное имя соответствующего пола. Старые кампании без сложности используют средний режим. Старое localStorage-сохранение импортируется только по кнопке игрока.

Генератор доступен как `StartupNameGenerator` в браузере и через `require('./name-generator')`: `generate(usedNames, gender?)`, `genderForName(name)`, `resolveIdentity(person)` и общий индекс `SPRITE_INDICES`. Длина имени ограничена 32 символами.

Система событий предоставляет `init()`, `reset()`, `onTick(state, callbacks)`, `onHire(state, callbacks)` и `pending`. `reset()` очищает временное состояние без возобновления таймера предыдущей игры. Очередь событий не является частью серверного сохранения.
